## 0. 왜 다시 하나 — 오너 지시 두 줄

> "전체적 ui 좀 손좀봐야겠는데 지금 너~무맘에안들어. 롤 + 소드아트온라인 + 메이플스토리
> 합친모드로해 (…) 가장중요한건 사람들이 게임하고싶게끔느껴지는 ui여야해. 캡쳐하고싶고."

> "아래 그 스킬이랑 체력바있고 이런거 가로로길게해서 좀 롤이나 메이플처럼해봐.
> 지금은 가운데 떠있어서 화면너무가림"

**판정 기준은 하나다 — "이 화면을 캡처해서 올리고 싶고, 보면 게임하고 싶어지는가."**
정밀 QA 는 "게임이 깨지는 수준"만 본다.

### 기각된 13차 판의 실측 (before, 1440x900 · 던전)

| 지표 | 13차(HEAD) | 롤 | 메이플 | 이번 목표 |
|---|---|---|---|---|
| 하단 계기판 **높이 / 화면 높이** | **17.9%** (161px) | 12~15% | 6.2% | **≤ 11%** |
| 하단 계기판 **폭 / 화면 폭** | **37%** | 51% | 100% | **≥ 60%** |
| 세로가 짧은 창(1000x560)에서 높이 | **25.7%** | — | — | ≤ 15% |
| 화면 가운데 칸(3x3 중앙) 침범 조각 | 1~3 | 0 | 0 | **0** |
| 판 색 | 아이보리 종이 | 어두운 유리 + 금테 | 밝은 회백 | 어두운 유리 |

★"가운데 떠 있다"의 정체는 **폭이 37% 인데 높이가 18%** 라는 것이다. 가로로 짧고
세로로 두꺼우니 화면 한복판 아래에 **덩어리**로 앉는다. 롤·메이플은 둘 다 그 반대다 —
**가로로 길고 세로로 얇다.** 같은 정보량이라도 가로로 펴면 가리는 면적이 줄고,
무엇보다 "떠 있는 카드"가 아니라 **화면의 아래 테두리**로 읽힌다.

## 1. 레퍼런스 해부

### 1-A. 리그 오브 레전드 — **레이아웃과 정보 위계**

측정 원본: `v99_wave13/uimaple2/ref/lol_01_full_hud_2560.png`(2560x1440 풀스크린) ·
`lol_03_ready_slots_practice.jpg` · `lol_04_legacy_hud.jpg` · 16차 수집분 `lol_1*.png`.

* **자리(4K 3장 + 2015판 교차검증 실측)** — HUD 는 **화면 아래 테두리에 붙은 가로 띠**다.
  3840x2160 기본 스케일에서 세로 `y1857~2152 = 295px = 13.7%`(레벨업 화살표 줄까지
  세면 16.6%), 가로 `x1096~2666 = 1570px = 40.9%`. HUD 아래 여백은 8px(0.4%) 로
  **사실상 바닥에 붙어 있다.** 유저가 HUD 스케일을 줄이면 8.3% 까지 내려간다
  (실사용 범위 8~17%). 미니맵만 오른쪽 아래에 따로 떨어진다(가로 14.2% x 세로 24.8%).
  **화면 가운데 위 2/3 는 통째로 비어 있다** — 챔피언이 늘 화면 정중앙에 서기
  때문이다(우리도 고정 쿼터뷰라 조건이 똑같다).
* **읽는 순서** — 왼쪽에서 오른쪽으로 `[스탯 판] → [초상 + 레벨 원] → [Q W E R + D F 슬롯]
  → [아이템 3x2 + 장신구] → [골드]`. 왼쪽이 "나", 가운데가 "내가 누를 것", 오른쪽이
  "내가 가진 것"이다. **누를 것이 한가운데** 있다.
* **슬롯** — 정사각형이다. 4K 기본에서 `113 x 110px`, **한 변 = 화면 높이의 5.2%**,
  피치 133px, 칸 사이 20px(**한 변 : 간격 = 5.6 : 1**). 소환사 주문은 QWER 의 73%,
  원형 초상 지름은 슬롯 한 변의 **2.12배**. 슬롯 **아래**에 레벨 점 5칸,
  슬롯 **위**에 최대 쿨다운, 슬롯 **안 한가운데**에 남은 초를 크게 쓴다.
  키캡(Q/W/E/R)은 슬롯 밖 아래에 걸린다.
* **게이지** — 체력 초록 / 자원 파랑 두 줄이 슬롯 열 **바로 아래**에 붙는다.
  ★**HP 바 폭 = 스킬바 폭의 99.8%.** 좌우 끝을 픽셀 단위로 맞춰 놓았다 —
  바-슬롯이 **한 덩어리**로 읽히는 것이 핵심이다. 바 두께는 슬롯 한 변의 27%.
  수치는 **바 안 한가운데**(843/1674), 재생량(+8.3)은 바 안 오른쪽 끝.
* **표면** — 어두운 반투명 판 + **금·놋쇠 각진 프레임**. 모서리는 둥글지 않고
  **깎여 있다(컷코너)**. 프레임 위쪽 가장자리에 얇은 금색 장식선.
* **캡처하고 싶어지는 지점** — 어두운 판 위에 **한 가지 밝은 색이 딱 하나씩** 산다
  (쿨다운 숫자의 흰색, 체력의 초록, 골드의 금색). 나머지는 전부 눌려 있다.

### 1-B. 소드아트온라인 — **표면 언어(재질·테두리·타이포)**

측정 원본: 16차 수집 `sao_01`~`sao_17`(전부 애니 화면 캡처, 팬메이드 0장).
아래 값은 **PIL 로 실제 픽셀을 샘플링**해서 뽑았다. 인상론이 아니다.

* **★★"SAO = 시안"은 틀렸다.** 아인크라드기 SAO 의 주액센트는 **주황·앰버**다.
  선택 행 `#ECB31A`(sao_03 근접컷) / `#DB9927`(sao_01) → 대표값 **`#E8A31E`**.
  시안·하늘색은 **보조**로만 산다(비석 이름 발광 sao_15, MP `#1C79A4`, 초상 타일 `#1874B2`).
* **판** — **흰 프로스트 유리**다. 어두운 유리가 아니다. 밝은 잔디 위(sao_07)에서
  내부가 `#ECECEC~#FDFDFD`, 어두운 벽돌 위(sao_01)에서 같은 판이 `#8F7561`.
  역산하면 **흰색 알파 0.35~0.42 + 배경을 탈색시키는 성질**. 뒤는 항상 비친다.
  대비를 **밝기가 아니라 채도**로 만든다(비선택=흰 유리, 선택=거의 불투명한 주황).
* **테두리** — 굵은 테도 시안 발광 테도 **없다.** 이게 사이버펑크 HUD 와의 결정적 차이다.
  가장자리를 1px 씩 스캔하면 배경 → 살짝 어두운 1px → 흰 바디로 **2px 안에 전환**.
  얇은 회색 헤어라인 + 약한 드롭섀도가 전부. 내부 구분선 `#C7C9CA` 1px.
* **모서리** — 기본 **완전 직각, 라운드 0**. 시그니처 변형 둘:
  (가) **45도 컷코너** — 게이지 끝단(sao_05/06/13), 좌우를 잘라 육각이 된 플레이트(sao_11)
  (나) **삼각 노치** — 메뉴 열을 잇는 화살표(sao_01/02), 판 아래 작은 꼬리(sao_09/12)
* **타이포** — 얇은 산세리프이되 정확히는 **각진 콘덴스드**(세로로 길고 폭이 좁고
  곡선을 직선으로 깎은). 대문자는 제목·시스템 낱말만. **자간은 제목에서만 넓다.**
  굵기가 하나뿐이라 위계를 크기와 색으로만 만든다.
* **게이지** — 아주 얇다. HP 채움 **12px = 화면 높이의 1.1%**. 트랙이 **있다**
  (어두운 회보라 반투명 `#646575`). 채움 위아래에 **흰 1~2px 선**.
  ★**끝 처리가 핵심: 오른쪽 끝이 45도 사선 컷. 둥근 캡은 절대 아니다.**
* **장식** — 아인크라드기 흰 UI 에는 **모서리 브라켓·스캔라인·육각·십자 마커가 없다.**
  쓰는 것은 넷뿐: 원형 아이콘 배지 / 삼각 노치 / **마름모 글리프**(◆BONUS ITEM◆, VS) /
  방사형 눈금. 장식이 몰린 예외는 둘 — sao_11(육각 벌집), **sao_14 앨리시제이션기
  다크 홀로 패널**(ㄱ자 브라켓 + 회로 배선 + 도트 스캔 + 십자 마커).
  → **규칙: 장식은 특수 상태에만.**
* **밀도** — 극단적 미니멀. 상시 표시는 좌상단 HP/MP 위젯 하나뿐, 화면 면적의 **1.7%**
  (568x63 / 1920x1080). 하단 바·미니맵·스킬 슬롯·퀵슬롯이 아예 없다.
  나머지는 모달성 창이고 열려도 화면의 15~35% 만 덮으며 한쪽으로 치우친다.
* **캡처하고 싶어지는 지점** — **UI 가 "게임 세계 안의 물건"으로 보인다.** 화면에
  덧씌운 껍데기가 아니라 주인공이 손으로 만지는 창이다. 그래서 캐릭터와 같이
  한 컷에 담긴다.

### 1-C. 메이플스토리 — **손맛·게이지·성장**

측정 원본: `v99_wave13/uimaple2/ref/maple_01~08` + 16차 수집분 `maple_1*.png`.

* **자리** — 최하단 **가로 100%** 띠. 세로는 화면의 6.2% 뿐이다(1916x1082 에서 67px).
* **띠 안 순서** — `[LV. 1 + 직업] → [HP 바 · MP 바 · EXP 바 3층] → [기능 버튼] → [퀵슬롯 키패드]`.
* **게이지** — 채도 높은 원색(HP 분홍-빨강 / MP 하늘 / EXP 노랑)이 꽉 찬다.
  위쪽에 광택 하이라이트 한 줄. **수치는 바 안에 대괄호로**(`[50/50]`).
* **EXP** — 맨 아래 한 줄. 얇지만 화면 전체를 가로지른다. "나는 자라고 있다"를
  화면이 늘 말하고 있다.
* **키캡** — 또렷한 사각 키캡에 키 이름이 박혀 있다. 무엇을 누르는지가 곧 UI 다.
* **캡처하고 싶어지는 지점** — **레벨업 연출.** 정보가 아니라 **축하**다.
  화면이 잠깐 나를 위해 멈춘다.

## 2. 조사한 분석글 (출처)

* Riot Games, "Clarity in League" — 공식 개발 블로그.
  <https://www.leagueoflegends.com/en-us/news/dev/clarity-in-league/>
  요지: **가장 중요한 것이 가장 큰 주목을 끌어야 한다.** "시각적 잡음은 빠르게
  쌓이고 한타에서 제대로 반응하지 못하게 만든다 — 잡음은 최소로 유지해야 한다."
  (이 글은 챔피언·스킨의 명료도를 다루지만, 위계와 잡음 원칙은 HUD 에 그대로 든다.)
* Riot Games, LoL HUD Update 개발 노트 요약(2015 HUD 개편).
  요지: **"플레이 공간을 가리지 않는(doesn't obscure the play space)" UI**,
  플레이어가 실제로 쓰는 방식대로 정보를 재배치, 쿨다운 표시의 모양·색·애니메이션을
  가독을 위해 바꿈. → 우리 파도의 오너 지시("화면 너무 가림")와 같은 문제의식이다.
* StraySpark, "Game UI/UX Design Principles: HUD, Menus, and Feedback Systems That Work".
  <https://www.strayspark.studio/blog/game-ui-ux-design-principles>
  가져온 규칙: **모서리 = 늘 떠 있는 정보(체력·미니맵), 가운데 = 순간 정보,
  가장자리 = 보조 정보.** 위계 4단(치명적→중요→정보→배경).
  **"Minimum Viable HUD" — 아무것도 없는 상태에서 시작해 화면을 차지할 자격을
  증명한 것만 더한다.** 전환 100~300ms, 입력 반응 16ms 이내.
* UI/UX 아트 디렉터, "7 obvious beginner mistakes with your game's HUD".
  <https://medium.com/design-bootcamp/7-obvious-beginner-mistakes-with-your-games-hud-from-a-ui-ux-art-director-d852e255184a>
  가져온 규칙: ① 정보 과다 → 위계로 접기 ② **디자인 툴이 아니라 실제 게임 화면 위에서
  검증** ③ 서체는 두 벌까지, 복잡한 배경 위에서는 테두리·판을 깐다 ④ **"뜨거운 색"
  하나만 정해 그것에만 준다. HUD 전체를 한 색으로 칠하지 마라** ⑤ 맨 숫자 대신
  **게이지·연출로** 보여라 ⑥ 관련된 것끼리 묶고 좌우 균형을 잡아라.
* Wayline, "Beyond the HUD: The Power of Diegetic Interfaces in Game Design".
  <https://www.wayline.io/blog/diegetic-interfaces-game-design>
  요지: **다이제틱 UI(세계 안에 있는 UI)는 미학적 업그레이드가 아니라 몰입 증폭기다.**
  → SAO 의 시스템창이 캡처되는 이유의 설명이다. 우리 게임은 "탑을 오르는" 설정이라
  "시스템창"이 세계관과 충돌하지 않는다.
* Resprawn/GameAnalytics 등, "juice" 계열 글.
  가져온 규칙: **juice 는 장식이 아니라 소통이다.** 히트스톱 1~3프레임, 화면 흔들림
  작은 사건 1~3px·큰 사건 5~10px, 버튼 hover 1.05x·press 0.95x.
  → HUD 에도 반응을 준다: 스킬이 준비되는 그 순간에 슬롯이 한 번 튄다.

## 3. 공통점과 상충점 — 무엇을 취했나

### 셋이 모두 하는 것 (그대로 가져간다)
1. **정보는 화면 가장자리에 붙는다.** 가운데는 비운다.
2. **수치는 게이지 안에 쓴다.** 게이지 옆이 아니다.
3. **누를 것은 정사각 슬롯**이고 그 위에 키가 적혀 있다.
4. **색은 뜻이다.** 빨강=위험, 초록=체력, 금색=보상. 장식으로 쓰지 않는다.

### 상충 ① SAO 의 **흰 유리** vs 우리가 쓸 수 없는 밝은 판 → **다크 홀로(sao_14) 채택**
실측대로라면 SAO 의 판은 흰 프로스트 유리다. 그런데 **13차 기각본이 바로 그
밝은 아이보리 판**이었다. 오너가 이미 한 번 물린 방향이고, 롤·메이플 클래식은
둘 다 어두운 판이다(메이플 클래식 하단 띠 `#2A2A2A~#4A4A4A`).
그래서 SAO 안에서도 **앨리시제이션기의 다크 홀로 패널**(sao_14) 쪽 문법을 취한다 —
같은 작품 안의 정당한 변주이고, 어두운 판 + 얇은 밝은 선 + 미세 그리드가 그 문법이다.
**대신 SAO 의 나머지는 그대로 가져온다**: 45도 컷코너 · 게이지 끝의 사선 컷 ·
채움 위아래 흰 1px 선 · 삼각 노치 · 마름모 글리프 · 모서리 해시 마크 ·
"장식은 특수 상태에만".

### 상충 ①-b SAO 의 **앰버** vs 시스템 UI 의 시안 → **뜻으로 갈라 둘 다 쓴다**
SAO 의 주액센트가 앰버라는 실측을 버리지 않는다. 대신 **색에 뜻을 준다.**
  **시안 = 시스템·기술·준비**(슬롯 · 창 테두리 · 라벨 · 기술 이름 팝)
  **앰버 = 목표·보상·성장**(목표 태그 · 레벨 뱃지 · EXP 띠 · 층 돌파 결과창)
  **빨강 = 위험**(보스 · 사망 · 체력 임계)  **초록 = 체력**(enemy.js 소유. 안 바꾼다)
앰버가 늘 보이는 자리(레벨 뱃지 · EXP 띠)에 앉으므로 화면에서 실제로 읽힌다.
그리고 이 배정은 세 레퍼런스가 전부 같은 자리에 쓰는 색이다 —
롤의 골드, SAO 의 선택 행 앰버, 메이플의 EXP 노랑.

### 상충 ② SAO 의 무채색 vs 메이플의 원색 게이지 → **"판은 무채, 게이지만 원색"**
판·테두리·글자는 무채색과 시안으로만 간다. **채도 높은 원색은 게이지 채움과
경고에만 준다.** 위 분석글의 "뜨거운 색 하나" 규칙과 같다.

### 상충 ③ 메이플의 가로 100% vs 롤의 가운데 51% → **롤을 취한다**
메이플은 2D 횡스크롤이라 화면 아래쪽이 원래 바닥이다. 우리는 쿼터뷰라 화면
아래쪽에도 지형과 적이 산다. **가운데 정렬 + 화면 폭의 62~76%** 로 간다.
다만 **EXP 띠만은 메이플처럼** 계기판 맨 아래 변을 가로지른다.

### 상충 ④ 메이플의 두꺼운 베벨 vs SAO 의 평면 → **평면**
13차가 기각된 직접 원인이 이 베벨(굵은 갈색 테 + 입체 그림자 + 통통한 라운드)이다.
**입체 그림자·이중 테·리벳·종이 결은 전부 제거한다.**

## 9. ★함정 (다음 사람이 같은 데 빠지지 않게)

1. **`clip-path` 는 바깥 그림자·발광을 통째로 자른다.** 컷코너 판에 `box-shadow` 로
   발광을 걸면 아무것도 안 보인다. **`filter: drop-shadow()` 를 쓸 것** — 그건
   잘린 실루엣을 따라간다. 늘 떠 있는 조각(계기판)에는 filter 를 안 건다.
2. **`clip-path` 를 건 판은 밖으로 나가는 자식을 전부 자른다.** 13차의 키캡은 슬롯
   **밖 아래**에 걸려 있었는데, 컷코너를 주는 순간 통째로 잘린다. 안으로 들였다
   (덤으로 계기판이 15px 낮아졌다).
3. **쿨다운 덮개(`.cd`)는 z-index 4 다. 키캡·이름을 그 밑에 두면 쿨이 도는 동안
   사라진다.** 첫 촬영에서 X·C 가 통째로 안 보였다 → `.key`·`.nm` 을 z-index 5 로.
   롤도 덮개 위에 키를 남긴다(무엇을 누를 칸인지는 쿨과 무관한 사실이다).
4. **`#bClear` 에 `position` 을 주지 말 것.** boss.js·level2.js 가 `position:fixed` +
   `translate(-50%,-50%)` 로 가운데를 잡고 있다. 덮으면 판이 화면 밖 아래로 사라진다.
   `transform` 을 덮을 때도 `translate(-50%,-50%)` 를 **반드시 같이** 적는다.
   그리고 그 판은 가상요소가 둘뿐이라(::before=위 표식, ::after=창 이름) 노치·해시가 없다.
5. **`index.html` 은 로딩 화면 CSS 의 독립 정본이다.** ui.js 의 `:root` 를 고치면
   여기도 같이 고쳐야 로딩과 게임의 판 색이 안 갈린다.
6. **UI 촬영 중에 진짜로 죽는다.** 몹 곁에 워프해 두고 반응형 컷을 찍으면 사망 카드가
   컷을 통째로 덮는다. 촬영 단계를 넘어갈 때 `__put` 으로 몹 곁을 뜰 것.
7. **`window.__enemy.positions` 는 getter 다**(함수가 아니다). `positions()` 로 부르면
   `TypeError`.
8. **계기판 높이가 바뀌면 은신 라벨(`#stHud`)의 `bottom` 도 같이 바꿔야 한다.**
   13차·14차가 두 번 밟았고 이번에도 값이 셋(88 / 82 / 74px) 다 바뀌었다.
9. **`setHelp(false)` 는 빈 판이다. 도움말을 촬영하려면 `toggleHelp()`.**
