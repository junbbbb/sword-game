# 탑 1층 던전 설계 — "어둠에 잠긴 회랑"

모티브: 「게임속 바바리안으로 살아남기」 1층. 갇힌 자들이 살아 나가려고 싸우는
석조 던전. 고블린만 나온다. 보스는 없다.

기존 초원 맵(`web/level1.*`, `blender/s20_level1.py`)의 **정반대**를 만든다.

| | 초원(level1) | 던전(level2) |
|---|---|---|
| 크기 | 96 x 96m | 56 x 56m |
| 칸 | 3.2m x 30 | 2.0m x 28 |
| 걸을 수 있는 면적 | 65% | 49% |
| 공간 | 열린 벌판 + 띄엄띄엄 막는 덩어리 | 방 8개 + 통로 12개 |
| 빛 | 봄 낮. 어디나 밝다 | 횃불·화로 49자루. 밝은 웅덩이와 어둠이 번갈아 온다 |
| 통로 폭 | 최소 6.4m, 주요 길 12.8m | 4.0m 고정 |
| 시야 | 너덜지대(1.45m)로 건너편이 보인다 | 앞벽 1.45m / 뒷벽 3.6m. 앞은 보이고 옆은 막힌다 |
| 끝내는 법 | 보스 격파 → 증표 → 문 | 제단의 증표 → 계단 |

산출은 기존 스키마 그대로다: `web/level2.glb` + `web/level2.json`.
`?map=field` 로 초원(level1)을 그대로 부를 수 있다(초원 파일 무변).

## 1. 방 그래프

```
                     [계단방 R_STAIR]   <- 잠긴 탈출 계단(증표 필요)
                        (남동)  ^
                                | K5
   [북서 R_NW]--K10--[제단 R_ALTAR]--K11--[북동 R_NE]
        |                    ^                  |
       K8                   K12                K9
        |                    |                  |
   [서 R_WEST]--K6--[중앙회랑 R_HALL]--K7--[동 R_EAST]
        |                    ^                  |
       K3                   K1                 K5
        |                    |                  |
        +----K2----[낙하방 R_ENTRY]----K4-------+
                    (여기서 시작)
```

* 갈림은 낙하방 **한 곳에서 셋**으로 벌어진다(서 / 가운데 / 동).
* 큰 고리가 하나 있다: 낙하방 → 서 → 북서 → 제단 → 북동 → 동 → 계단방 → 낙하방.
  중앙 회랑은 그 고리를 세로로 가로지르는 **지름길**이고, 값이 있다(5마리 캠프).
* **막다른 길 0개.** 방 여덟 개가 전부 출입구 2개 이상을 갖는다.
  계단방조차 두 갈래(낙하방 쪽 K4, 동쪽 방 쪽 K5)로 이어져 고리 위에 있다.
* 첫 층이라 **함정은 없다.**

### 문폭

* 통로 폭 **4.0m 하나로 통일**한다. 방과 방 사이의 벽에 이 폭만큼 구멍이 뚫린 것이 곧 문이다.
* 왜 4.0m 인가: `web/nav.js` 가 1.6m 격자에 **반경 0.55m** 로 "설 수 있는 칸"을 판정한다.
  폭 W 통로에서 실제로 통과 가능한 띠는 `W - 1.1m` 다. 4.0m 면 2.9m 가 남아
  1.6m 칸이 **최소 두 줄** 살아남는다. 3.0m 로 좁히면 1.9m 만 남아 칸 한 줄이
  격자 위상에 따라 통째로 죽는 자리가 생긴다(= 요괴가 문을 못 지나간다).
* 문 자리에는 양쪽에 문설주(0.40m 각기둥)를 벽 면 위에 걸터앉히고 그 위에 인방석을 얹는다.
  **콜라이더는 안 붙인다.** 벽 콜라이더가 이미 0.22m 안으로 들어가 있어서 문설주가
  내미는 0.20m 는 그 여유 안이다 - 통과 폭이 한 톨도 안 줄어든다.
* ★그래서 벽 콜라이더 인셋이 0.22m 다. 0.06m 로 구웠더니 통과 띠가 2.78m 로 줄어
  K2·K4·K12 세 통로가 nav 한 줄로 떨어졌다(= 요괴가 문에 끼는 자리). 0.22 면 띠가
  3.34m > 3.2m 라 **격자 정렬과 무관하게** 두 줄이 보장된다.

## 2. 몹 배치 의도

`web/enemy.js` 는 **마릿수를 맵에서 안 받는다.** `groupsFromMobs()` 가
`count = 3 + (i % 3)` 로 정한다. 즉 **`mobs[]` 의 순서가 곧 마릿수 배분**이다.
(enemy.js 는 이 작업의 소유 밖이라 한 글자도 안 건드린다.)

| i | 마릿수 | 자리 | 의도 |
|---|---|---|---|
| 0 | 3 | R_WEST 서쪽 창고 | 첫 전투. 3마리는 정면으로 붙어볼 만하다 |
| 1 | 4 | R_EAST 동쪽 감옥 | 한 마리가 늘면 옆구리를 잡힌다 |
| 2 | **5** | R_ALTAR 제단 앞 | **정예.** 목표를 몸으로 막는다 |
| 3 | 3 | R_NW 북서 우물방 | 서쪽 고리의 두 번째 |
| 4 | 4 | R_NE 북동 취사장 | 동쪽 고리의 두 번째 |
| 5 | **5** | R_HALL 중앙 회랑 | **지름길의 값.** 가운데로 곧장 가면 5마리를 정면으로 받는다 |

합계 24마리. 어그로 7m, 리쉬 24m(enemy.js).

* **캠프 간 거리 17m 이상**을 지킨다(어그로 7m 두 개가 안 겹쳐야 "한 무리만 떼어낸다"가 성립).
  던전은 벽이 있어 초원보다 유리하다. 실제 최소 간격은 빌드 스크립트가 재서 찍는다.
* 제단 캠프는 제단보다 **남쪽 4m** 에 둔다. 북쪽에서 들어오는 경로가 없으므로
  플레이어는 어느 길로 오든 이 다섯을 지나야 증표에 닿는다.
* 순찰은 따로 안 만든다. enemy.js 의 최소 무리가 3마리라 "순찰 1~2"를 만들 창구가 없고,
  억지로 3마리 무리를 통로에 흩뿌리면 방 캠프와 어그로가 겹쳐 위 규칙이 깨진다.
  대신 **캠프 반경을 방마다 다르게** 줘서(2.2 ~ 3.0) 서 있는 모양이 방마다 달라 보이게 한다.
* 보스는 없다. `level2.json` 에 `boss` 키를 **안 넣는다**. 각귀(boss.glb)는 이 층에 안 뜬다.

## 3. 증표와 탈출 (기존 符 / 門 문법 재사용)

* 증표(符)는 **제단 위에 처음부터 놓여 있다**(`altar` 필드). 보스가 떨구지 않는다.
* 줍는 순간 위치가 노출된다는 규칙은 그대로다. 상단 문구가
  「증표를 들고 남쪽 계단으로 · 고블린들이 증표를 쫓는다」로 바뀐다.
* 탈출구는 **계단 하나뿐**이다(`EXIT_1`, 계단방 한가운데). 門 글리프 그대로.
* 동선 길이가 뜻이 있다: 제단은 북쪽 끝(z = -21), 계단은 남동쪽(z = +19).
  증표를 들고 **40m 를 되짚어 나와야** 한다. 올 때 정리한 방이라도 25초면 다시 찬다
  (enemy.js GROUP_RESPAWN 25초). "들고 살아 나가기"가 그래서 성립한다.
* 계단은 판이 시작할 때부터 **보인다**(동쪽 갈래 끝). 잠겨 있다는 사실이 먼저 오고
  증표가 나중에 온다. 목표를 설명하는 문장이 필요 없어진다.

## 4. 빛과 색 — **컨셉 아트를 재현한다** (13차B 전면 재작업)

1차는 이 절의 숫자를 감으로 적었고 오너에게 **"미감이 하나도 없잖아"** 로 기각당했다.
2차는 순서를 뒤집었다. 컨셉 아트(`incoming/codex_dungeon/concept_hall.png`)가 먼저
확정됐고, 이 절은 **그 그림을 숫자로 옮긴 기록**이다.

### 4-0. 무엇이 달랐는가 (실측)

| | 컨셉 | 1차 게임 화면 | 2차 게임 화면 |
|---|---|---|---|
| 전체 평균 | `#181e25` S .33 V .15 | 따뜻한 회색 S .10 V .45 | `#181c24` S .30 V .15 |
| 어둠 바닥 | `#1a1f28` V .16 | — | `#0e1826` V .16 |
| 깊은 구석 | `#031021` **S .90** | — | 남색 S .7~.8 |
| 달빛 바닥 | `#26578e` S .73 V .56 | 없음 | 있음 |

1차의 실패는 조명 코드가 아니라 **세 가지 색 결정**이었다.
 ① 바닥 목표색이 `#302d29` = R>G>B 따뜻한 회갈색이었다(컨셉은 R<G<B 찬 돌).
 ② 화면 밝기 V 45% 였다(컨셉은 15%).
 ③ 어둠에 채도가 없었다(컨셉의 어둠은 **짙은 남색**이다).

### 4-1. 색을 세 층으로 나눈다

```
  ① 씬 조명 (web/main.js 던전 분기)   찬 달빛.  E = (0.391, 0.565, 0.864)
  ② 정점색 (COLOR_0, s40 이 굽는다)   어둠의 깊이 · 웜/콜드 기울기 · N·L
  ③ 이미시브 데칼 (s40 이 굽는다)     웜 풀 · 달빛 웅덩이 · 샤프트 · 불꽃
```

③ 이 2차에서 새로 생긴 층이고, 이게 없으면 컨셉의 그림이 **원리적으로 안 나온다**:
COLOR_0 은 1 에서 잘리므로 밝은 쪽이 어두운 쪽의 (1/AMB)배를 못 넘는데, 컨셉의
횃불 코어와 구석 어둠은 화면 선형으로 30배 차이다. 이미시브는 조명·정점색 계약
밖이라 그 폭을 자유롭게 낸다.

### 4-2. 씬 조명 (초원과 갈린다)

|  | 초원(level1) | 던전(level2) |
|---|---|---|
| 배경·안개색 | `#9fc2d8` | `#0b1420` |
| 안개 | near d+2 / far d+30 | **near d+1 / far d+17** |
| 반구광 | `0xcfe4f2`/`0x5b5140` 1.55 | `0x6f9ad2`/`0x161f30` 1.70 |
| 키(해/달) | `0xfff0d4` 2.35 @(5,9,4) | `0xc4d8f0` 1.70 @**(2.5,12,3.5)** |
| 림 | `0x9dc8ee` 0.55 | `0x3f6ea6` 0.45 |
| 윗면 조도 E | (0.99,0.99,1.00) 휘도 .99 | **(0.391,0.565,0.864) 휘도 .55** |

* 키를 **세운다**(2.5,12,3.5). 그림자를 짧게 만들려는 것이다 — 던전에서 긴 그림자가
  대각으로 누우면 그 순간 실외가 된다. 접지 그림자 자체는 손맛이라 남긴다.
* `E` 는 팔레트의 근거다. **여기 숫자를 바꾸면 던전 색이 통째로 밀린다.**

### 4-3. 팔레트 — 감이 아니라 ACES 역산

```
    알베도 = tools/color_contract.py 의 screen_to_paint(화면목표, E)
```

|---|---|---|
| 바닥 판석 | `#1d2634` | `494745` |
| 벽 석재 | `#17202e` | `414041` |
| 기둥·아치·문설주 | `#2b3543` | `5a5551` |
| 제단 | `#343546` | `645553` |
| 계단 | `#1b2a3e` | `474b4d` |
| 잔해 | `#202834` | `4d4945` |

### 4-4. 정점색 (COLOR_0) — 넷이 곱해진다

```
정점색 = clamp( (AMB + Σ 광원) x 높이감쇠 + 이끼 , AMB_MIN , 1 )
광원_i = 색 x 세기 x w^2.4 / (1 + (d/R)^2) x (0.42 + 0.58 max(0, N·L))
w      = max(0, 1 - d / (R x 2.5))          R = 4.3m · 세기 0.98
```

* `AMB = (0.165, 0.205, 0.305)` — 파랑/빨강 **1.85**. 어둠이 회색이 아니라 남색이 되는 자리.
* **★N·L 이 2차에서 그림을 제일 크게 바꾼 한 줄이다.** 1차는 정점색이 거리만 봐서
  기둥·아치·벽이 사방 똑같은 밝기가 됐고, 쿼터뷰에서 통째로 납작한 판으로 읽혔다.
  면 법선을 뉴웰로 구해 광원 방향과 내적하면 횃불 쪽 면이 밝고 반대쪽이 죽는다 =
  컨셉에서 기둥이 둥글게 보이는 바로 그 장치다.
* **높이 감쇠**: 2.20m 위로 3.20m 동안 0.42 까지 어두워진다. 벽 상단이 어둠에 녹아
  천장 없는 쿼터뷰 던전이 성립하고, 1차의 "하늘 샘" 인상이 여기서 봉인된다.
* **이끼**: 벽에서 1.15m 안쪽 바닥에 초록을 더한다(컨셉의 이끼는 판 한가운데가 아니라
  줄눈과 벽 밑동에 낀다).
* 웜 풀 감마가 `w^2` 에서 `w^2.4` 로 올랐다. 선형 감쇠는 웅덩이가 아니라 **넓은 얼룩**이다.

### 4-5. 이미시브 데칼 — "빛을 물건으로 그린다"

컨셉의 횃불은 **세 장**으로 그려져 있다: 불꽃 + 바닥에 번진 주황 웅덩이 + 벽에 번진
자국. 달빛도 세 장이다: 콘 + 바닥 타원 + 먼지. 1차는 불꽃 삼각형 하나뿐이었다.

| 메시 | 텍스처 | 이미시브 | 알파 상한 | 크기 |
|---|---|---|---|---|
| `FLOOR_POOL` | `dg_pool.png` | 0.26 | 0.52 | 반경 2.15~3.1m |
| `FLOOR_POOLC` | `dg_pool_cold.png` | 0.78 | 0.78 | 반경 2.1~2.3m |
| `FLOOR_SHAFT` | `dg_shaft.png` | 0.60 | 0.36 | 판 3장 x 7.0~7.6m |
| `FLOOR_FLAME` | `dg_flame.png` | 3.40 | 1.00 | 십자 2장 |
| `FLOOR_MEDAL` | `dg_medallion.png` | 0.45 | 비네트 | 반경 3.05m |

* **★알파 상한이 제일 중요한 손잡이다.** 1.0 이면 데칼이 바닥돌을 덮어서 빛이 아니라
  물감 웅덩이가 된다(첫 굽기에서 실제로 그랬다).
* **★이미시브 세기는 2 를 넘기면 안 된다.** ACES 가 주황을 흰색으로 말아 올려서
  "웜 풀"이 "흰 얼룩"이 된다. 불꽃 심지만 그 위로 보낸다.
* 달빛 샤프트는 **두 자리에만** 둔다(낙하방 · 중앙 회랑). 늘리면 천장이 통째로 무너진
  집이 되고 어둠이 정보를 잃는다.

### 4-6. 타일 — 컨셉 시트에서 잘라 온다

`tools/dungeon_tex.py` 가 `incoming/codex_dungeon/tiles_dungeon.png` 4분할을 굽는다.

```
  좌상 이끼 낀 판석 -> web/tex/dg_floor.jpg      (방 바닥,  UV 4.5m)
  우상 석벽 블록    -> web/tex/dg_wall.jpg       (벽·기둥,  UV 2.8m)
  좌하 금 간 바닥   -> web/tex/dg_floor_b.jpg    (통로 바닥, UV 4.5m)
  우하 메달리온     -> web/tex/dg_medallion.png  (제단 데칼, 알파 비네트)
```

공정: ① 큰 명암 얼룩 제거 ② Moisan periodic 분해로 이어붙임화(`tools/tileize.py` 재사용)
③ 최고주파만 살짝 눌러 지글거림 규격 ④ **선형 스칼라**로 밝기 정규화(sRGB 평균 0.58).

* ④ 가 필요한 이유: 재질 곱수가 1 을 못 넘으므로(glTF 규격) 타일이 목표색보다 밝아야
  한다. 원자재가 sRGB 평균 `#2a312c` 로 아주 어두워서 선형 x11~15 를 곱한다.
  **선형 스칼라 곱은 채널 비를 그대로 두므로 채도가 안 상한다** — 화면에서 다시
  어두워질 때 원래 색으로 정확히 돌아온다(밝게 구운 타일이 파스텔로 보이는 것은
  노출 착시다).
* 이음매 실측: 가로 `+128% -> -65%` / 세로 `+97% -> -67%` (세 장 모두 기준 안).
* 평균은 도구가 재서 `web/tex/dungeon_tex.json` 에 적는다 —
  **블렌더 파이썬에는 PIL 이 없어서 s40 이 png 평균을 스스로 못 잰다.**

### 4-7. 재질 곱수 계약 (초원과 같되 손잡이가 하나 늘었다)

```
화면색 = baseColorFactor x 타일 x 정점색
곱수 = (1-hue_keep) x [채널별: 목표색/타일평균/정점평균]
     +    hue_keep   x [스칼라: 목표휘도/타일휘도/정점휘도]
```

* `hue_keep`(기본 0.55, 벽만 0.34)이 **타일의 색기를 얼마나 살릴지**다. 컨셉 타일의
  청록 돌 + 이끼 초록이 이 판의 미감이라 절반 넘게 살린다.
* **휘도는 hue_keep 과 무관하게 정확히 보존된다**(항등식). 그래서 자기 검증은
  채널이 아니라 휘도로 잰다 — 휘도가 어긋나면 그건 곱수가 1 에서 잘린 것이다.

## 5. 벽 높이 — 쿼터뷰가 정하는 값

카메라는 고정 쿼터뷰다(main.js: pitch 0.86rad · dist 24 · **yaw 0**).
yaw 가 0 이라 카메라는 언제나 플레이어의 **남쪽(+z)** 에 있다. 그래서

> 벽이 플레이어를 가리는 경우는 **그 벽이 플레이어보다 남쪽에 있을 때뿐**이다.

카메라에서 내려오는 시선의 기울기는 `sin(0.86)/cos(0.86) = 1.16` 이다.
플레이어에서 남쪽으로 d 만큼 떨어진 벽은 높이가 `1.16 x d` 를 넘으면 발치를 가린다.

여기서 규칙 하나가 나온다.

| 벽 칸의 조건 | 높이 | 왜 |
|---|---|---|
| **북쪽 이웃 칸이 걸을 수 있다** | **1.45m** (앞벽) | 그 칸에 선 플레이어에게 이 벽은 남쪽이다 = 화면 아래쪽 전경이다. 1.45m 면 1.25m 안까지 붙어야 가려진다 |
| 남쪽 이웃 칸이 걸을 수 있다 | **3.6m** (뒷벽) | 화면 위쪽 배경이다. 높아야 방이 닫힌다. 13차B 에서 3.1 -> 3.6 (아치가 3.0m 까지 올라간다) |
| 둘 다 아니다(속 채움) | 3.6m | 안 보이는 자리. 뒷벽과 같이 둬야 마루가 이어진다 |
| 맵 바깥 테두리 | 7.5m (남쪽만 4.2m) | 화면 끝을 막는 배경. 1차가 4.2m 라 화면 위 구석에 하늘이 샜다 |

* 벽은 **두 칸(4.0m) 두께**로 둘러친다. 그래서 방 사이 벽은 언제나
  「앞벽 1.45m + 뒷벽 3.1m」 두 겹이 된다. 남쪽 방에서 북쪽을 보면 3.1m 벽이 서 있고,
  북쪽 방에서는 그 벽의 반대쪽 1.45m 짜리가 화면 아래에 낮게 깔린다.
  **한 벽이 방향에 따라 다르게 보인다** — 천장 없는 쿼터뷰 던전이 원래 그렇게 생겼다.
* 천장은 안 만든다. 벽 윗면(마루)만 한 단 밝게 칠해 두께가 읽히게 한다.
* **13차B 추가.** 벽이 벽돌 벌판으로 읽히지 않게 두 가지를 얹었다.
  ① 방마다 네 벽에 **붙임기둥**을 세 칸에 하나씩 (뒷벽 몇 자리에는 낡은 깃발)
  ② 앞벽(1.45m) 위에 **부서진 관석**을 띄엄띄엄 (콜라이더 없음. 높이만 얹는다).
  ★관석 자리는 칸 좌표 해시로 뽑는다 - 공용 RND 를 쓰면 스트림이 밀려서 아래 잔해
    배치가 통째로 바뀐다(실제로 그래서 nav 섬이 한 칸 생겼다).

## 6. 자기 검증 (빌더가 굽는 자리에서 잰다. 눈으로 안 본다)

빌더 `blender/s40_dungeon1.py` 가 아래를 재고, 하나라도 어긋나면 그 자리에서 소리를 지른다.
13차B 실측값을 같이 적는다(전부 통과).

1. **연결성** — 스폰에서 flood fill(1.6m 격자 · 반경 0.55) 해서 방 8개와 제단·계단·
   캠프 6곳에 전부 닿는가. 섬이 한 칸도 없어야 한다 (**467 / 467 = 100%**)
2. **막다른 길** — 방마다 출입구가 2개 이상인가 (**0개**)
3. **통로 여유** — 통로 단면마다 nav 칸이 두 줄 이상 (**12개 통로 전부 2줄 이상**).
   ★통로의 참 중심으로 재야 한다(짝수 칸에서 `(c0+c1)//2` 는 한 칸 어긋난다)
4. **스폰 정면** — 스폰 앞 5m x 폭 3.0m 에 콜라이더가 없는가.
   ★소품 배제 창과 검사 범위가 같은 상수를 봐야 한다. **13차B 에서 여기가 두 번 울렸다** —
   세워 둔 화로와 받침대형 횃불이 스폰 통로에 들어갔다. 배치 쪽에 같은 배제 창을 넣어 고쳤다
5. **캠프 간격** — 무리 자리끼리 17m 이상 (**17.8m**)
6. **증표 접근** — 제단 반경 1.7m(TOKEN_PICK_R) 안에 설 수 있는 자리가 있는가
7. **횃불 자리** — 자루마다 실제로 벽 칸이고 앞벽(1.45m)이 아닌가 (**38자루 전부**)
8. **색 규칙** — 바닥의 화면 평균 밝기 > 벽 (**0.0635 > 0.0517, 1.23배**)
9. **곱수 계약** — 재질 곱수가 전부 1.0 이하이고 **화면 휘도**가 목표에서 6% 안인가
   (11개 재질 전부 오차 0.0%). ★채널이 아니라 휘도로 재는 이유는 4-7 절에 있다
10. **빛의 리듬** — 바닥 정점밝기의 최대-최소 폭이 0.30 이상인가
   (**0.21 ~ 1.00**. 여기가 0 이면 어둠도 웜 존도 없는 균일한 판이다)
11. **예산** — 삼각형 **49,014** · glb **4.78MB** (5MB 상한)
