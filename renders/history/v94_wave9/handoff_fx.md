## 0. 무엇을 고쳤나 — 한 문장

**"화면에 그은 획"이 없었다.** 큰 획은 처치한 프레임에만 그어졌고, 평소 화면을 채우던 것은
칼날 축을 폭으로 쓰는 월드 리본이라 고정 쿼터뷰에서 지면에 깔린 깔개로 보였다.
이제 **휘두를 때마다** 화면 좌표에 붓획이 세 장 깔리고, 월드 리본도 폭을 카메라 평면에서
캐릭터 **바깥으로** 편다.

## 1. 계약 두 개를 어떻게 동시에 지켰나

두 심사 판정이 정면으로 부딪쳤다.
- 손맛: "이펙트가 판정의 3~5배 과장" → **작아져야 한다**
- 이펙트: "화면 점유 0.5~1.4% vs 귀멸 15~57%" → **커져야 한다**

**답: 축을 갈랐다.**

| | 무엇으로 재나 | 어디에 묶었나 |
|---|---|---|
| **길이**(벤 방향) | 판정 리치 3.2m · 정면 부채꼴 ±75° | `REACH_R` / `REACH_COS` / `SL_LEN` 상한 |
| **굵기**(획에 수직) | 화면 존재감 | 획 세 장 겹침 · 세로 스윕 · 머리 장식 · 먹 튀김 |

획에 수직인 방향은 **아무 거짓말도 안 한다**. "저기까지 벴다"고 말하는 것은 길이뿐이다.
그래서 길이는 판정에 못 박고, 굵기·겹침으로만 화면을 채운다.

**지속 계약**: 본 획은 24fps 기준 **4프레임(0.167초)** 만 살고 사라진다.
잔상은 궤적 리본의 **가는 먹 자취 두 칸**(폭 30%·16%)뿐이다.
예전에는 궤적 세기가 `0.92^프레임` 로 삭아 0.41초를 갔다 — 그게 "0.3~0.9초 덮음"의 절반이었다.

## 2. 격차별로 무엇을 했나 (심사 인용 → 조치)

### ① "귀멸은 화면에 그은 획, 게임은 지형 원근에 눕는 깔개"
- **화면공간 본 획 신설** (`feel.swing`, main.js 궤적 구역에서 호출).
  스윙마다 본 획 1 + 동반 획 2 = **세 장**이 화면 좌표에 깔린다. 처치 여부와 무관하다.
  스윙 감지는 `enemies.swing` 이 아니라 **칼끝 속도**로 한다 — 요괴가 없어도 획은 그어져야 한다.
- **궤적 리본의 폭 방향을 카메라 평면으로**. 예전엔 리본 면 = (칼날 축) x (시간) 이라
  가로베기에서 면이 통째로 수평이 됐다. 이제 칼날 축은 **중심선의 자리**만 정하고,
  폭은 화면에서 **플레이어로부터 바깥으로** 편다.
- **지면 전개 축소**: 무리 전멸 링 지름 7.4 → 5.2m.
- 속도선은 원래도 화면 겹이었지만 "3D 말뚝"으로 읽혔다 → 줄 밀도 17→27, 퍼짐 폭 절반,
  길이 0.62배, 양끝 뾰족, **렌더 순서 41 → 39**(본 획 **아래**로 깔았다).

### ② 먹선이 형태를 정의
- **진범은 색 하나였다.** `PAL_WATER.ink` 가 `#1428c8` — 그건 먹이 아니라 **밝은 파랑**이다
  (상대휘도 0.20 · 채도 100%). 같은 시트로 그린 처치 초승달은 ink 가 `#2a0710` 이라 51% 로
  합격했는데 파랑 획만 11~14% 였던 이유가 여기다. → `#081228`(감청 먹, 휘도 0.045).
- 몸통 먹 밴드 0.30→0.10 을 **0.44→0.20** 으로, 전환 폭 0.05 → 0.02.
- 포말(리본 실루엣의 **바깥 끝**) 먹 띠 0.74 → 0.60, 색 `C_DK2*0.5`.
- 가는 심 먹 띠 30% → 42%. 물보라 윤곽 띠도 넓히고 `uPal[0]*0.7` 로 눌렀다.
- **바깥 끝 안티에일리어싱 폭 0.016 → 0.006.** 이 한 겹이 화면에서 경계 1픽셀을 배경과
  반반 섞어서, 먹 밴드를 아무리 두껍게 그려도 심사관이 재는 링은 중간 명도로 나왔다.
- 새 시트 `slash_flip2.png` 는 12칸 전부 먹선 **100%**(`tools/bake_slash_wide.py` 자체 검증).

### ③ 평칠 + 흰 심
- `PAL_WATER` 를 귀멸 실측 팔레트로: 먹 `#081228` → 감청 `#0c3c9c` → 밝은 시안 `#24ccfc`
  → 흰 심 `#cce4fc`. 예전에는 상위색이 중간 명도 파랑에만 몰려 있었다.
- `wave_water.png` 는 **재포스터라이즈하지 않았다**(v92 기록: 이미 평칠 띠 그림이라 밝기를
  다시 뭉개면 띠가 합쳐진다). 먹 밴드만 넓혔다.
- **등간격 평행 띠의 진짜 원인은 텍스처가 아니라 UV 였다.** 수명이 여섯 칸으로 짧아지면서
  살아 있는 마디가 버퍼의 앞 10% 뿐인데 `u` 는 여전히 버퍼 전체에 걸쳐 0..1 이라,
  손그림의 갈라지는 붓결이 **앞 10%만 늘어나** 등간격 줄무늬가 됐다.
  → 살아 있는 창으로 정규화한 `un` 을 쓴다(길이 테이퍼도 같은 값으로 잰다. 안 그러면
  꼬리가 안 뾰족해져 뭉툭한 판때기가 된다).

### ④ 비처치 타격 프레임
- **타격 팝** 신설(`feel.pop`). 명중 접점에 24fps 기준 두 장: f0 흰 번쩍(찢긴 흰 덩어리 +
  굵은 먹 테두리) → f1 먹 튀김(방사로 튄 쉼표꼴 먹 방울 + 흰 심).
  게임시계로 늙는다(히트스톱 중 한 장 홀드). 절차 셰이더라 텍스처가 없다.
- 처치에도 같이 찍는다(size 1.15 / 비처치 0.9).

### ⑤ 더블 패널 병합
- `PANEL_MERGE = 0.80초`. 창 안의 추가 처치는 **백색 패널을 다시 안 띄운다** —

### ⑥ wrap/spray 양자화
- 감는 리본·물보라가 v92 이후로도 **60fps 로 매끈하게** 흐르고 있었다(v92 가 스스로 신고).

## 4. 다른 파일 소유자에게 (내가 못 고치는 것)

### A. [main.js 후처리 · 9B-1 또는 성능 소유자] ★MSAA 가 격프레임으로 꺼진다
계측 중에 발견한 **실제 렌더 버그**다. 이펙트와 무관하지만 화면 전체에 영향을 준다.

```
main.js:106   if (composer.renderTarget2) composer.renderTarget2.samples = 0;
```
`EffectComposer` 는 rt1/rt2 를 **번갈아** 쓴다(RenderPass 가 needsSwap 이고 스왑 상태가
다음 render 까지 남는다). 그래서 씬 패스가 한 프레임은 samples=4, 다음 프레임은 samples=0
타겟에 그려진다 = **MSAA 가 30Hz 로 깜빡인다.**

실측(세계 완전 정지, 같은 태스크 안 연속 렌더): 1↔3↔5 완전 동일, 1↔2↔4↔6 은
**6,648px(전체 0.72%)이 최대 172/255 · 평균 30.5 차이**. 차이 화소는 정확히
바위·수풀·플레이어·칼의 **실루엣 가장자리**뿐(증거 `fx/measure/w9b2m_diag_parity.png`).
눈에는 가장자리가 30Hz 로 떠는 것으로 보인다.

★이걸 모르면 A/B 계측이 통째로 거짓말이 된다 — 정지 화면인데도 마스크가 6,633px 잡힌다.
계측 스크립트는 **한 장당 두 번 그리고 두 번째를 읽어** 패리티를 고정하는 것으로 우회했다.

### B. [enemy.js] 타격 팝과 겹으로 노는 것
명중마다 접점에 흰 번쩍 + 먹 튀김이 뜬다. A3 가 넣은 **적 플래시·경직 0.13초**와 같은
프레임에 걸린다. 둘이 같이 뜨는 것이 의도다 — 한쪽을 줄일 거면 알려 달라.

### C. [level.js] 물 셰이더는 안 건드렸다
`patchWaterMaterial` 의 캐시 키 `waterLook6` 그대로다. 이펙트 쪽에서 수면 재질에
`onBeforeCompile` 을 문 곳은 0건이다.

## 6. 함정 (다음 사람이 또 밟을 것들)

- **셰이더 유니폼 배열 길이를 손으로 세지 마라.** `uP: { value: [1,1,1] }` 처럼 박아 두면
  `SLOTS` 를 3 → 5 로 올리는 순간 `uOff.value[3]` 이 `undefined` 가 되고 `.set()` 에서
  게임 루프가 통째로 죽는다. Playwright 에는 "Execution context was destroyed" 로만 보여서
  GPU 크래시로 오진했다. 반드시 `mkNum(SLOTS, ...)` 꼴로 만들 것.
- **수명을 짧게 하면 UV 정규화를 같이 고쳐야 한다.** 마디 인덱스는 버퍼 전체에 걸쳐 0..1
  인데 살아 있는 건 앞 10% 뿐이면, 텍스처도 테이퍼도 그 10% 안에서만 일어난다.
  증상은 "뭉툭한 판때기 + 등간격 평행 띠"로 나타나서 원인을 텍스처에서 찾게 된다.
- **폭 방향을 '접선의 화면 수직'으로 잡으면 두 가지가 깨진다.** ① 획이 캐릭터를 한가운데
  놓고 위아래로 부풀어 몸이 사라진다(캐릭터 심사 FAIL 을 그대로 재현했다) ② 접선이 시선과
  나란해지는 마디에서 **부호가 뒤집혀** 리본이 나비넥타이처럼 접힌다(큰 직선 사각형이
  화면에 뜬다). **반지름 방향**(플레이어 → 중심선)으로 잡으면 둘이 같이 없어진다 —
  호의 접선에 수직인 방향이 곧 반지름이고, 부호가 구조적으로 안 뒤집힌다.
- **한 획을 뚱뚱하게 만들어서는 존재감이 안 나온다.** 길이가 리치에 묶여 있으므로 굵기만
  키우면 가로세로 비가 1:1 로 가고, 그 그림은 붓이 아니라 **돛**으로 읽힌다(실측 스크린샷).
  귀멸의 큰 기술 컷도 한 획이 뚱뚱한 게 아니라 **2~3획이 겹쳐** 화면을 채운다.
- **샘플에 태생 프레임(`e.f`)을 안 넣는 경로가 있다.** DEV 굽기 창구(`__bakeTrail`·
  `__bakeWrap`)가 그렇다. 그러면 나이가 NaN → 폭이 NaN → **정점 좌표가 NaN** 이 되어
  화면이 한두 프레임 새까매진다(v88 '검은 번쩍'과 같은 기전). 없으면 '방금 태어남'으로
  접는 방어를 넣어 뒀다.
- **1/24 게이트를 넣으면 DEV 굽기 창구가 갇힌다.** 클립을 손으로 미는 경로는 `gameT` 가
  안 흘러서 첫 호출 말고는 아무것도 안 그린다. `force` 인자를 반드시 뚫어 둘 것
  (`updateTrail(force)` 가 쓰던 것과 같은 방식으로 `updateSpray`·`updateWrap` 에도 넣었다).
- **합격작은 시트까지 고정해야 지켜진다.** 처치 백색 패널·진홍 초승달이 건틀릿의 유일한
  합격작이라 손대면 안 되는데, 시트 한 장을 갈아 끼우면 **그 둘의 그림도 같이 바뀐다.**
  그래서 시트를 두 벌로 갈랐다: 화면 겹 붓자국만 `slash_flip2.png`, 초승달·패널은
  `slash_flip.png` 그대로.
- 계측 중에 소스를 고치면 그 계측은 통째로 못 쓴다. 실제로 한 번 겪었다(중간 상태에서
  잰 "before" 가 이미 절반쯤 after 였다). **파일 해시를 계측 산출물에 박아 둘 것.**

## 7. 실측

`fx/measure/` 에 원자료가 있고, 정의 정본은 `fx/measure/w9b2m_manifest_before.json` 이다.
계측 정의 요약:
- **먹선 비율** = 이펙트 마스크의 1px 경계 링 화소 중 **상대휘도 < 48/255** 인 비율.
  링 = mask AND NOT erode(mask,1). 휘도는 감마 sRGB 값에 Rec.709 계수.
  **캘리브레이션**: 귀멸 실프레임 6장에 같은 정의를 먹여 평균 55.4%(4/6이 40~63 안).
- **이펙트 마스크** = 한 태스크 안에서 (이펙트 켠 화면) vs (이펙트 메시만 끈 화면) 의
  채널 최대차 > 12/255. ★MSAA 패리티(위 4-A) 때문에 한 장당 두 번 그려야 정지 화면
  마스크가 0 이 된다.
- **결정적 60fps**: `window.__slow = 1/3` 이면 `rawDt` 가 정확히 1/60 로 고정된다
  (계측 한 장이 0.3초 걸려 실델타가 늘 0.05 상한에 걸린다). 프레임 수 / 60 = 초.

수치표 원본은 `fx/measure/w9b2m_final_after.json` · `w9b2m_final_true_before.json`.
★`before` 태그가 붙은 산출물은 **작업 중간 상태**에서 잰 것이라 쓰면 안 된다.
진짜 개선 전은 `true_before` 다(v93 백업을 제자리에 넣고 다시 쟀다. 되돌린 뒤 해시 대조 통과).

### 못 채운 것 — 왜 못 채웠나 (다음 사람이 판단할 것)

**① 화면 점유 12~30%.** 지금 4.7~9.0% 다. 세 번 시도해서 얻은 결론:
- 획을 통째로 1.3배 키웠더니 점유는 **15% 밖에** 안 올랐다. 획 넷이 서로 **겹쳐서**
  새 면적이 안 생긴다. 면적은 굵기가 아니라 **간격**에서 나온다(그래서 일격기만
  간격을 1.75배로 벌려 8~9% 를 만들었다).
- 더 키우면 **다른 계약이 깨진다.** 같은 변경으로 처치 프레임 몸 가림이 0.15 → 0.32초로
  나빠졌다(획을 몸에서 더 밀어내 되돌렸다).
- 남은 정직한 길은 **길이**인데 그건 리치 계약이 막는다. 귀멸의 15~57% 는 화면을 가로지르는
  획에서 나오고, 우리 획은 3.2m 안에 갇혀 있다(고정 쿼터뷰에서 3.2m = 화면 가로의 20%).
- ★오너 판단이 필요하다: **평타에도 화면의 6분의 1을 덮는 물이 매번 지나가는 게 맞는가.**
  맞다면 리치 계약을 "한 획의 길이"가 아니라 "스윙 호의 현(chord)"으로 다시 정의해야 한다
  (±75° 부채꼴의 현은 6.2m 이고, 그것도 판정 안이다).

**② 먹선 40%.** 21/24 미달(17~44%). 계열로 갈린다 — **백아(감청)가 통째로 낮고**(17~39,
40 도달 0건) 녹슨 칼은 명중 세 동작이 42~44 로 넘겼다. 감청 획의 경계 휘도가 아직
문턱 0.188 위에 있다는 뜻이다. 다음 손잡이는 `PAL_WATER.edge`(#0c3c9c, 휘도 0.13)를
경계 밴드에서만 한 단 더 누르는 것이다.

**③ 처치 프레임 몸 가림.** 0.117~0.233초로 늘었다. 백색 패널을 한 번으로 줄였는데도
화면 겹 획 넷 + 초승달 + 팝이 같은 프레임에 겹친다. 처치에서는 동반 획을 빼는 것이
제일 싼 수다(본 획 한 장 + 초승달이면 그림은 그대로 산다).
