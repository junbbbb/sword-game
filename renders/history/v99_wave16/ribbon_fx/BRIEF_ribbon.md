## 9.1 ★★진범을 내가 숫자로 찾아 놨다 — 사다리가 통째로 위에 몰려 있다

> 즉 "밴드를 다섯 단 칠했다"는 코드의 주장은 참인데,
> **그 다섯 단이 화면에서 서로 구별이 안 된다.** 그래서 통짜 흰 판이다.
> 먹선(`C_DK2 * 0.42`)만 겨우 어둡고 나머지는 전부 같은 밝기 덩어리다.

이게 지난 두 판에서 "밴드 비율을 만졌는데 그림이 안 바뀐다"의 정체다.
**비율의 문제가 아니라 사다리의 자리(range)의 문제다.**

### 내가 이 표에서 읽은 것 (너의 눈으로 반박해도 된다)
1. **밴드는 그라데이션이 아니라 평칠 계단이고, 계단 사이에 얇은 먹(K2~K3)이 낀다.**
   `N4 K2 N13`, `N3 K2 N2`, `N2 K3 N22` — 2~3px 짜리 먹이 밴드를 **구획**한다.
   지금 게임에는 이 내부 먹선이 **아예 없다**(먹은 바깥 테두리 한 겹뿐).
2. **편측이다.** 흰(W)은 늘 **바깥 끝 한 덩어리**, 두꺼운 먹(K10~K36)은 늘 **안쪽**.
   지금 게임 셰이더도 편측(bt)은 맞다. 색의 자리가 아니라 **색의 값**이 틀렸다.
3. **흰 밴드 폭이 길이축을 따라 단조로 사그라든다**: 55 → 51 → 44 → 38 → 27 → 16 → 5 → **0**.
   ★알파 커브가 아니라 **밴드 폭 커브**다. 오너가 말한 "알파도 밴드별로 다르게 사그라든다"의
   실물은 이것이다 — 원작은 알파를 안 쓴다(작화라 알파가 없다). **밴드가 좁아지다 사라진다.**
   이건 우리 계약(알파는 유/무만. §3.2)과 **충돌하지 않는다.** 폭으로 하면 된다.
4. **몸통은 두세 가닥이 두꺼운 먹(K24~K36)으로 갈라져 있다.** 한 가닥이 아니다.
   각 가닥이 제 사다리를 갖는다(`... C58 M2 N20 | K36 | N10 M2 C19 M2 N5 ...`).
   지금 B 는 가닥이 둘인데 하나는 headOnly 마루(w 0.09)라 사실상 몸통 한 가닥이다.
5. **가장 넓은 단일 밴드는 시안(C)이다**(32~60px = 폭의 20~35%). 흰이 아니다.
   머리(ref_1)에서만 흰이 압도한다(W95~118). **머리 3칸만 흰 잔치, 나머지는 청색.**

## 9.3 ★네가 반드시 풀어야 하는 모순 하나

귀멸 단면에서 **흰은 리본의 바깥 끝**이다. 그런데 우리 엔진에서는 그 자리에
**이미 feel.js 의 포말 마루층이 서 있다**(지난 라운드 산출물. 리본 바깥 0.08m).

- 리본이 지금처럼 바깥 끝을 흰색으로 칠하면 → **흰 위의 흰** = 지난 라운드가 실패한 그 기전.
- 리본 바깥 끝을 먹·감청으로 내리면 → 포말의 흰이 어두운 이웃 위에 서서 **살아난다.**
  대신 리본 자체에는 "바깥의 흰 심"이 없어진다.

내 가설(강제 아님): **포말층이 곧 귀멸 단면의 바깥 흰 밴드다.** 리본은 그 아래
`얇은 먹 이음선 → 감청 → 중청 → 시안(제일 넓음) → 중청 → 감청 → 두꺼운 먹(안쪽)` 으로
가고, 리본 자체의 흰 심은 **머리 2~3칸에서만** 가는 띠로 나온다.
이러면 두 층이 합쳐 귀멸 단면 한 벌이 된다.

**네가 다르게 판단하면 그렇게 해라.** 다만 어느 쪽이든 아래 자를 통과해야 한다:
- QA 자 ①「거품이 리본 밖 **어두운** 배경에 서는 비율」 현행 **66.6%** — 유지 또는 개선.
- QA 자 ②「밴드 조성」 흰(W) 비율을 **82% → 25% 이하**로. 먹(K)+감청(N)을 **합계 25% 이상**으로.

### 리본의 기하가 실제로 어떻게 만들어지나 (읽고 시작해라)
- `trailBuf[]` = 매 1/24 칸마다 밀어 넣는 **칼날 선분**(`{a,b,t,f}`). 최대 `FX.trailMax`(B=34).
- `updateTrail(force)` 가 그 34개를 **Catmull-Rom 으로 RIBS=140 마디**로 보간해
  `STRANDS(=FX.cfg.length) × 140 × 2` 정점을 매 칸 다시 쓴다.
- 폭의 단위는 **미터가 아니라 "칼이 쓸고 간 방(room)의 비율"**이다:
  `room = outCap - BODY_R`, `outCap = min(OUT_R, max(BODY_R+0.10, tipR*FX.tipK))`.
  `half = C.w * room * taper * headK * edgeK * gK`, 상한 `room*0.48`.
- 정점 애트리뷰트:
  | 이름 | 뜻 |
  |---|---|
  | `aUV.x` (= 셰이더 `u`) | 길이. **0 = 칼끝(머리)**, 1 = 꼬리. 살아 있는 창 기준(`un`) |
  | `aUV.y` (= `v` = `bt`) | 폭. **0 = 몸 쪽(안쪽)**, **1 = 칼끝 쪽(바깥)** |
  | `aAlpha` (`vA`) | B 는 `'binary'` → **1.0 아니면 0**. 반투명 없음 |
  | `aSeed` (`vSeed`) | **가닥 번호**(cfg 의 `kind`). B 는 2(마루) / 0(본 리본) |
  | `aHalf` (`vHalf`) | 이 마디의 반폭(**미터**). 셰이더가 `uPxPerM` 과 곱해 **화소**로 환산 |
  | `uPxPerM` | 1m 가 화면에서 몇 화소인가(플레이어 깊이 기준). 매 칸 갱신 |
- 셰이더가 이미 갖고 있는 자:
  `dE`(대칭 가장자리 거리) · `bt`(편측) · `cut`(붓 갉음, 1/24 재시딩) ·
  `dN`(갉인 뒤 정규화) · `ea`(1px 알파 컷) · `halfPx` · `ow`(먹 3~4화소) · `rw`(갓선).
  **`ow`/`rw` 를 화소로 잡는 이 방식은 유지해라** — 비율로 잡으면 가는 마디에서 선이 0px 이 된다
  (v96 이 밟았다). 내부 구획 먹선을 넣더라도 같은 자로 잡아라.

### B 몸통 채색의 현행 전문 (1017~1070) — 무엇이 흰 판을 만드나
```
sc   = floor(uT*24)/24                      // 1/24 스크롤
tlum = wave_water 텍스처 밝기               // 0..1
bs   = clamp(bt + (tlum-0.5)*0.55, 0, 1)    // 밴드 자리를 질감이 밀고 당긴다
c    = bs<0.42 ? C_DK1 : bs<0.64 ? C_MID : bs<0.78 ? C_LT1 : bs<0.90 ? C_LT2 : C_LT3
ws   = min(0.90, 1 - clamp(3.4/halfPx, 0.06, 0.18))
if (bs > ws) c = C_WHT                      // 흰 심(바깥 한 겹)
c   *= 0.74 + 0.44*tlum                     // ★최대 1.18배 → 블룸 문턱 1.02 초과
fo   = noise(u*13, bt*4)
if (bt > 0.62) { fo>0.62 ? c = C_WHT : fo>0.54 ? c = C_DK2*0.55 }   // ★바깥 38%에 흰 점 잔치
if (dN < ow) c = C_DK2*0.42; else if (dN < rw) c = C_LT3            // 먹/갓선(바깥 한 겹뿐)
ls   = min(1, floor(u*4)/3);  c = mix(c, C_DK1, 0.30*ls)            // 꼬리 감청
```
내가 보는 범인 셋(반박 가능):
1. `C_DK1`~`C_WHT` 다섯 단이 화면 176~207 — **사다리가 없다**(§9.1).
2. `c *= 0.74+0.44*tlum` 이 **1.18배까지 올린다** → 화면 209 위 → 블룸 → 번져서 더 흰 판.
3. `bt>0.62` 흰 점 규칙이 **바깥 38% 를 흰색으로** 덮는다. 귀멸의 흰은 바깥 15~22%다.

## 9.5 지켜야 하는 것 (어기면 판이 되돌아간다)

`foam_fx/BRIEF_codex.md` §3 전부 + 아래.

1. **`?fx=a|c|d` 는 한 화소도 안 변한다.** 공용 코드를 고치면 `FX.mode===1` / `uMode` 로 가둬라.
   내가 a/c/d 를 캡처해 화소 대조로 검증한다.
2. **`ELEMENTS` 팔레트 금지.** B 밴드색은 `uPal[]` 에서 **파생**시켜라(배수·믹스).
   B 는 **7자루 칼 전부**가 쓴다(물/불/얼음/독/흙/어둑 + 봉인칼은 style 1 로 빠진다).
   물만 맞추고 불이 깨지면 탈락이다.
   ★참고로 배수 파생이 실제로 되는 것은 내가 확인했다 —
   `uPal[0]×0.20 → 화면 V40 · uPal[1]×0.22 → V71 · uPal[2]×0.42 → V126 · uPal[3]×0.82 → V184`
   가 물·불·얼음·어둑 넷 모두에서 성립한다(색상은 각자 유지). **예시이지 지시가 아니다.**
3. **알파는 유/무만.** 반투명 구간을 되살리지 마라 — 밝은 모래 바닥과 섞여 채도가 통째로 깎인다
   (v98 실측). 꼬리의 사그라듦은 **밴드 폭**으로 해라(§9.2-3 이 실측 근거다).
4. **24fps.** `floor(uT*24.0)` 재시딩·스크롤 계단을 유지해라. 60fps 로 미끄러지면 CG 다.
5. **NormalBlending · `depthWrite:false` · renderOrder 3** 유지. 가산합성 금지.
6. **NaN 계약**: 알파 검사는 `if (!(vA > 0.004)) discard;` 꼴로만.
7. **크기**: 화면 점유 정점 3~7%(상한 9%) · 주인공 머리·상체 덮임 상한 60% ·
   `BODY_R 0.82` 안에 한 화소도 안 그린다 · 리치 3.2m/±75° 밖 금지.
   현행 정점은 Z 1.32 · X 2.22 · C 1.41 · 처치 2.11% 다(내 BEFORE 실측. **올릴 여지가 크다**).
8. **롤백 한 줄.** `main.js` 에 상수 하나(예: `const RIBBON_V2 = 1;`)를 두고
   0 으로 내리면 지금 그림으로 통째로 돌아가게 해라. 보고서에 그 상수 이름을 적어라.
9. **`FX_TABLE.b.sprayK = 0.0` 유지**(오너가 기각한 물방울). 되살리지 마라.
10. **성능**: 정점 수(STRANDS×140×2)를 늘리면 그만큼 매 칸 CPU 루프가 는다.
    가닥을 3~4로 늘리는 것은 허용하되 그 이상은 fps 왕복을 네가 근거로 대라.

## 9.6 feel.js 포말층과의 계약 (읽되 수정 최소화. 인터페이스 유지)
